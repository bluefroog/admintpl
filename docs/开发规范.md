# 开发规范

> 本文档为项目内约定俗成的开发规范，所有开发必须遵循。项目基于 Go + Gin + GORM（模块：`github.com/bluefroog/admintpl`）。

---

## 一、代码放置规范

### 1.1 目录职责

| 目录 | 职责 |
| --- | --- |
| `app/system/` | **系统管理**模块（路由前缀 `/system/...`）：用户/角色/部门/菜单/岗位/字典/参数/公告/日志/认证 |
| `app/monitor/` | **系统监控**模块（路由前缀 `/monitor/...`）：在线用户/登录日志/操作日志/服务监控/缓存监控 |
| `app/cron/` | **定时任务**模块（路由前缀 `/monitor/job...`、`/monitor/jobLog/...`）：任务配置/调度器/任务日志/内置调用目标 |
| `app/gen/` | **代码生成**模块（路由前缀 `/tool/gen/...`）：表结构导入/生成配置/同步数据库表结构/模板渲染与下载 |
| `app/<模块>/controller/` | HTTP 控制器层：路由处理函数 + swag 接口注解。只做「绑定参数 → 校验 → 调用 service → 返回响应」，不写业务逻辑 |
| `app/<模块>/controller/init.go` | 模块路由注册中心：`InitRouter` 中统一注册本模块路由（`authorized` 分组挂 `middleware.Auth()`） |
| `app/<模块>/service/` | 业务逻辑层：数据库操作（`common/database.DB`）、唯一性校验、分页排序等 |
| `app/<模块>/domain/` | 数据模型层：GORM 实体、请求/响应结构体 |
| `app/<模块>/domain/init.go` | 本模块 `Models()` 模型注册（**新增表模型必须加到这里**） |
| `app/<模块>/initialize.go` | 模块初始化入口：注册路由 + 模块级启动逻辑（如调度器、种子数据） |
| `app/<模块>/test/http/` | 各表的 `*.http` 接口测试文件 |
| `common/database/` | 数据库层：`DB` 全局句柄、`InitDB`、`AutoMigrateAll`、`TableEmpty` |
| `common/sysinfo/` | 服务器指标采集：标准库读取 `/proc`（平台无关解析 + 构建标签拆分平台实现） |
| `common/cache/` | 进程内内存缓存：过期清理、读写统计、缓存注册表（供缓存监控） |
| `bootstrap/` | 启动编排：初始化数据库 → 迁移各模块模型 → 依次初始化各模块 → swagger |
| `common/model/request/` | 通用请求结构体：`request.PageInfo`（分页）、`request.SortInfo`（排序）、`request.GetById`、`request.IdsRequest` |
| `common/model/core/` | 公共模型：`core.AuditModel`（CreateTime/CreateBy/UpdateTime/UpdateBy/Remark） |
| `common/model/response/` | 统一响应结构：`response.PageResult` |
| `common/response/` | 响应辅助函数：`response.OK` / `response.Fail(-1, ...)` / `response.Success` |
| `common/validate/` | 结构体参数校验：`validate.Struct` |

### 1.2 文件与命名规范

- **每张表对应一套文件**，文件名 = 表名（蛇形），例如表 `sys_dict_type` → `dict-type.go`（controller / service / domain / http 同名）。
- **类型命名** = 表名转驼峰 + 后缀：
  - 实体：`Xxx`（`ID uint` + `XxxBase` 嵌入 `core.AuditModel`）+ `TableName()` 方法
  - 列表搜索：`XxxSearchRequest`（嵌入 `request.PageInfo`、`request.SortInfo`、`core.RouyiSearchRequest`，含 ID/IDIn/IDNotIn 等过滤字段）
  - 新增：`XxxCreateRequest`；修改：`XxxUpdateRequest`（嵌入 `request.GetById`）
  - 关系表（复合主键，无自增 ID）额外定义 `XxxDeleteRequest`（外键用指针类型 `*uint`，可只传部分条件）
- **控制器包内实例变量**：`xxx = service.Xxx{}`（小驼峰）。
- **服务层标准方法**：`GetCount` / `GetList` / `parseFilter` / `Create` / `Update` / `UpdateByMap` / `Delete` / `Detail`，唯一性校验用 `XxxIsExist`（基于 GetCount 查询）。

### 1.3 接口路由规范

按模块注册在各自 `controller/init.go` 的分组下，路径 = `<模块前缀>/<表名>/<动作>`：

| 模块 | 注册文件 | 路径前缀 |
| --- | --- | --- |
| 系统管理 | `app/system/controller/init.go` | `/system/<表名>/<动作>` |
| 系统监控 | `app/monitor/controller/init.go` | `/monitor/<表名>/<动作>` |
| 定时任务 | `app/cron/controller/init.go` | `/monitor/job/<动作>`、`/monitor/jobLog/<动作>`（定时任务归属「系统监控」菜单） |
| 代码生成 | `app/gen/controller/init.go` | `/tool/gen/<动作>`（代码生成归属「系统工具」菜单） |

| 动作 | 方法 | 说明 |
| --- | --- | --- |
| `/list` | GET | 列表（分页查询） |
| `/create` | POST | 新增 |
| `/update` | PUT | 修改（日志表/关系表不提供） |
| `/delete` | DELETE | 删除（日志表用 `request.IdsRequest`，关系表用 `XxxDeleteRequest`） |
| `/detail` | GET | 详情（`request.GetById`，日志表/关系表不提供） |

- **业务表**（用户、部门、角色、菜单、字典、任务等）：全量 list/create/update/delete/detail。
- **日志表**（登录日志、操作日志、任务日志）：仅 list/delete/detail。
- **关系表**（角色部门、角色菜单、用户岗位、用户角色，复合主键）：仅 list/create/delete。

**扩展动作**（在标准 CRUD 之外按模块按需提供，路径仍为 `<模块前缀>/<表名>/<动作>`）：

| 动作 | 方法 | 说明 |
| --- | --- | --- |
| `/tree` | GET | 树形数据（部门、菜单），返回扁平 `[]domain.Ztree`，由前端组装成树 |
| `/role-dept-tree`、`/role-menu-tree` | GET | 角色数据权限 / 菜单授权树（带勾选） |
| `/check-name`、`/check-key`、`/check-perms`、`/check-type`、`/check-code`、`/check-label`、`/check-username`、`/check-mobile`、`/check-email` | GET | 唯一性校验，返回 `bool` |
| `/reset-pwd`、`/change-status`、`/password`、`/avatar`、`/profile` | PUT | 密码重置、状态变更、个人资料维护 |
| `/roles`、`/posts` | GET/PUT | 用户角色 / 岗位的查询与授权（先删后插） |
| `/menu`、`/data-scope` | PUT | 角色菜单授权、角色数据权限（含自定义部门） |
| `/allocated-list`、`/unallocated-list` | GET | 角色已分配 / 未分配用户列表 |
| `/select-users`、`/cancel-user`、`/cancel-users` | POST/DELETE | 角色批量授权与取消授权 |
| `/get-by-key`、`/get-by-type`、`/list-all` | GET | 按业务键取值（参数）、按类型取值（字典） |
| `/clear` | DELETE | 日志清空（登录日志按 status，操作日志全量） |
| `/refresh-cache` | DELETE | 刷新缓存（参数：`/system/config/refresh-cache`；字典：`/system/dict-type/refresh-cache`），返回缓存条目数 |
| `/force-logout` | DELETE | 强退在线用户（按 token） |

### 1.4 响应规范

- 成功带数据：`response.OK(data, c)`
- 成功仅提示：`response.Success("xxx成功", c)`
- 失败：`response.Fail(-1, "xxx失败: "+err.Error(), c)`

### 1.5 控制器标准流程

```
绑定参数(c.Bind) → validate.Struct 校验 → 调 service 方法 → response.OK/Fail 返回
```

### 1.6 特殊规则

- 树形结构表（部门、菜单）：删除前必须检查子节点（`ParentIDIn` 查询，存在子节点则禁止删除）。
- 关联表清理：删除用户必须同步删除 `sys_user_role`、`sys_user_post`；删除角色必须同步删除 `sys_role_menu`、`sys_role_dept`、`sys_user_role`（事务内执行）。
- 日志表 Create 仅系统内部使用，不对外提供路由。
- 新增 `.go` 文件与项目保持一致使用 **CRLF** 行尾。
- **零值写入**：带 `default:` 标签的列在「结构体方式 Create」时会用数据库默认值覆盖零值
  （如 `is_frame` 默认 1、`status` 默认 1、`menu_check_strictly` 默认 1），此类表的 Create 必须用
  `map[string]interface{}` 显式写入（见 `service/menu.go`、`service/user.go`、`service/role.go`）；
  带非零默认值的字段新增时请补一条冒烟校验，防止回归。

### 1.7 登录认证与权限

- 登录接口（免鉴权，注册在 `authorized` 分组之前）：

| 路径 | 方法 | 说明 |
| --- | --- | --- |
| `/captchaImage` | GET | 图形验证码（`uuid` + base64 PNG；开关关闭时 `captchaEnabled=false`） |
| `/login` | POST | 登录，入参 `{username, password, code?, uuid?}`，返回 `{token, expiresIn}` |

- 需鉴权接口（注册在 `app/system/controller/init.go` 的 `authorized` 分组，已挂 `middleware.Auth()`）：

| 路径 | 方法 | 说明 |
| --- | --- | --- |
| `/logout` | POST | 退出登录 |
| `/getInfo` | GET | 当前登录用户信息 + 角色标识 + 权限标识 |
| `/getRouters` | GET | 当前用户前端路由（Layout/ParentView/外链） |
| `/system/**` | - | 全部业务接口 |

- **令牌**：64 位随机串，登录时写入 `user_online` 表，请求头 `Authorization: Bearer <token>`（兼容 `token` 请求头与 `?token=`）。
- **权限标识**：`/system/<模块>/<动作>` -> `system:<模块>:<动作>`（与菜单 `perms` 一致）；
  `system/user/profile|password|avatar` 为自助接口，不参与权限校验；超级管理员（`IsAdmin` 或用户 ID 1）与 `*:*:*` 直接放行。
- **业务方法获取当前用户**：`middleware.GetLoginUser(c)` / `GetUserID(c)` / `GetUsername(c)`，
  不再使用 `// todo 通过登录服务获取` 占位。
- **开关**：`AUTH_ENABLED`（关=全部免登录，仅调试用）、`AUTH_TOKEN_EXPIRE`、`AUTH_MAX_RETRY`、`AUTH_LOCK_TIME`、
  `AUTH_PERMISSION_ENABLED`、`CAPTCHA_ENABLED`、`CAPTCHA_LENGTH`、`CAPTCHA_EXPIRE`、`SEED_ENABLED`。
  新增开关必须同步 `config/config.yaml` + `.env.dev` + `.env.pro`（`common/config/config_test.go` 会校验键名与取值）。

### 1.8 定时任务

- **接口**（`sys_job` 表，控制器 `app/system/controller/job.go`）：

| 路径 | 方法 | 说明 |
| --- | --- | --- |
| `/system/job/list` `/create` `/update` `/delete` `/detail` | - | 任务增删改查（新增/修改校验 cron 与调用目标） |
| `/system/job/change-status` | PUT | 启用（`status=0`）/ 暂停（`status=1`） |
| `/system/job/run` | PUT | 立即执行一次（暂停中的任务同样可执行） |
| `/system/job-log/list` `/detail` `/delete` | - | 任务执行日志 |

- **cron 表达式**：统一用 `common/cron`（Quartz 语义，6~7 段 `秒 分 时 日 月 周 [年]`），
  支持 `*` `?` `,` `-` `/` `L` `W` `#` 与 `JAN-DEC` / `SUN-SAT`；
  日与周都指定时取「或」关系，未使用的一侧写 `?`；周字段 `1~7` 为周日~周六（兼容 `0` 表示周日）。
- **调用目标**：`bean.method(args)`，参数支持字符串（单/双引号）、整数、浮点数、布尔值；
  只能调用 `app/system/task/task.go` 中 `task.Register(...)` 注册过的方法，未注册直接拒绝。
- **调度器**：`app/system/service/job-scheduler.go`，按秒扫描 + 独立协程执行；`concurrent=1` 时同一任务不并发，
  `misfire_policy`（1 立即执行 / 2 执行一次 / 3 放弃执行）用于启动时补偿停机期间错过的执行；执行结果写 `sys_job_log`。
- **联动**：任务新增/修改/启停后调用 `JobScheduler{}.Refresh(id)`，删除调用 `Remove(id)` 并按 `job_name + job_group` 清理日志；
  任务表 Create 使用 map 写入（`concurrent`/`status`/`misfire_policy` 带默认值）。
- **开关**：`JOB_ENABLED`（是否启动调度器）、`JOB_LOG_RETAIN_DAYS`（日志保留天数，启动时清理）。

### 1.9 数据权限

- **实现位置**：`app/system/service/data-scope.go`（`DataScope`），仅对「非超级管理员 + 已登录 + 开关开启」生效。
- **数据范围取值**（`sys_role.data_scope`，`0` 视为 `1`）：

| 值 | 含义 | 生成的过滤条件 |
| --- | --- | --- |
| 1 | 全部数据权限 | 不追加条件 |
| 2 | 自定义数据权限 | `<dept列> IN (SELECT dept_id FROM sys_role_dept WHERE role_id = ?)` |
| 3 | 本部门数据权限 | `<dept列> = 登录用户 department_id` |
| 4 | 本部门及以下数据权限 | `<dept列> IN (SELECT dept_id FROM sys_dept WHERE dept_id = ? OR FIND_IN_SET(?, ancestors))` |
| 5 | 仅本人数据权限 | `<user列> = 登录用户ID`（无 user 列时生成 `1 = 0`） |

- **拼接规则**：多角色按 OR 合并为 `(条件1 OR 条件2)`；任一角色为 `1` 则不限制；无角色 / `loginUser=nil` / 关闭开关时不追加条件。
- **用法**：

```go
// 列表方法新增 loginUser 参数，查询条件拼接完成后追加数据权限
func (s User) GetList(searchParams *domain.UserSearchRequest, loginUser *domain.LoginUser) (*response.PageResult, error) {
    db := domain.DB.Model(&domain.User{})
    // ... 其它过滤条件
    db = DataScope{}.Apply(db, loginUser, DataScopeOptions{DeptColumn: "department_id", UserColumn: "id"})
    // ... 分页查询
}
// 角色列表：按「角色下的用户是否在可见范围内」过滤
db = DataScope{}.ApplyToRoles(db, loginUser)
```

- **控制器**：`GetList(&searchParams, middleware.GetLoginUser(c))`；内部唯一性校验、子节点检查等场景传 `nil`（不受数据权限影响）。
- **取值校验**：角色新增/修改/数据范围保存统一调用 `NormalizeDataScope`，`1~5` 之外返回「数据范围不正确」。
- **开关**：`DATA_SCOPE_ENABLED`（`system.data-scope.enabled`，默认 true）。

### 1.10 参数 / 字典缓存

- **缓存语义**：`sys_config`（`config_key -> config_value`）与 `sys_dict`（`dict_type -> []DictData`）缓存在进程内（`common/cache`，无 Redis），
  启动时预热，读取时缓存优先，写操作（新增/修改/删除）后失效，支持手动刷新缓存。
- **实现位置**：`app/system/service/config.go`、`app/system/service/dict-data.go`；字典类型变更（`dict-type.go`）会清理相关字典缓存。
- **刷新接口**：`DELETE /system/config/refresh-cache`（返回参数条目数）、`DELETE /system/dict-type/refresh-cache`（返回字典类型数）。
- **开关**：`CACHE_ENABLED`（`system.cache.enabled`，默认 true）；关闭后所有读取直接回源数据库，便于排查「改了配置不生效」。
- **调试**：两个缓存都注册到缓存监控，可在「缓存监控 / 缓存列表」按缓存名称（`sys_config`、`sys_dict`）过滤查看键值。

### 1.11 代码生成（app/gen）

| 接口 | 方法 | 权限标识 | 说明 |
| --- | --- | --- | --- |
| `/tool/gen/list` | GET | `tool:gen:list` | 代码生成表列表（`table_name` / `table_comment` / 时间范围过滤） |
| `/tool/gen/db-list` | GET | `tool:gen:db-list` | 数据库表列表（未导入的表） |
| `/tool/gen/column-list` | GET | `tool:gen:column-list` | 字段配置列表（按 `table_id`） |
| `/tool/gen/detail` | GET | `tool:gen:detail` | 表详情（表配置 + 字段配置 + 主键列 + 树表参数） |
| `/tool/gen/import` | POST | `tool:gen:import` | 导入表结构 |
| `/tool/gen/update` | PUT | `tool:gen:update` | 修改生成配置 |
| `/tool/gen/synch-db` | POST | `tool:gen:synch-db` | 同步数据库表结构 |
| `/tool/gen/delete` | DELETE | `tool:gen:delete` | 删除生成配置（同时清理字段配置） |
| `/tool/gen/preview` | GET | `tool:gen:preview` | 预览生成代码（返回「文件相对路径 -> 文件内容」） |
| `/tool/gen/download` | GET | `tool:gen:code` | 下载生成代码（`application/zip`，沿用「生成代码」权限） |

- **表**：`gen_table`（`table_id` 主键）、`gen_table_column`（`column_id` 主键），模型在 `app/gen/domain/`，注册于 `app/gen/domain/init.go` 的 `Models()`；
- **命名冲突**：`domain.Table` 需要 GORM 的 `TableName()` 方法，故表名字段命名为 `Name`（JSON 仍为 `table_name`），不要再加同名的字段或方法；
- **表结构来源**：`information_schema.tables` / `information_schema.columns` 原始查询（GORM `Table(...)`），不引入任何第三方元数据表；
  已导入的表用子查询排除，`qrtz_%`、`gen_%` 前缀表不参与导入；导入是事务操作，已导入的表会跳过（全部已导入时报错）；
- **默认配置推导**：`app/gen/service/field.go` 的 `InitTable` / `InitColumnField` / `SetPkColumn`；
  修改规则必须同步补 `field_test.go` 用例（`dbType`/`camelCase`/列名后缀判断等纯函数均已单测覆盖）；
- **路由命名**：使用扁平化动作名（`db-list`、`column-list`、`synch-db`）而非 `/db/list`、`/column/list`，
  这样 `middleware.PathPermission` 可直接按 `/tool/**` 前缀推导权限标识（`tool:gen:db-list`），无需在 `pathPermissionAlias` 中补别名；
- **配置项**：`system.gen.package-name` / `module-name` / `author` / `auto-remove-pre` / `table-prefix`（对应 `GEN_*` 环境变量），禁止在代码中写死；
- **`gen_table` 只能通过导入接口写入**，因此不提供 `create` 接口（避免出现与实际表结构不一致的脏配置）；
- **模板渲染**：`app/gen/service/render.go`（渲染上下文 + zip 打包）与 `app/gen/service/templates/*.tmpl`（`embed.FS` 内置）；
  **只用标准库 `text/template` + `archive/zip` + `go/format`**，禁止引入模板引擎或第三方代码生成库；
  生成文件路径固定为 `app/<模块>/{domain,service,controller,test/http}/<表名>.go|.http`、`docs/sql/<表名>.sql`、
  `app/<模块>/<表名>.register.md`（接入说明：模型注册 / 路由注册 / 权限标识 / 字段对照 / 注意事项）；
- **渲染取值优先级**：`gen_table` 按表配置（`package_name`/`module_name`/`class_name`/`function_name`/`function_author`）
  > `system.gen.*` 全局配置 > 表名推导；文件名固定取「表名去前缀后的蛇形名」（不取 `business_name`，避免多段表名丢信息）；
- **主键约束**：只支持整型主键，实体字段统一 `ID uint`、搜索参数 `ID *uint`、删除 `[]uint`，非整型主键在渲染前直接报错。

### 1.12 服务监控 / 缓存监控

| 接口 | 方法 | 权限标识 | 说明 |
| --- | --- | --- | --- |
| `/monitor/server` | GET | `monitor:server:list` | 服务监控：CPU/内存/Go 运行时/主机/磁盘 |
| `/monitor/cache` | GET | `monitor:cache:list` | 缓存监控：各内存缓存的键数量与读写统计 |
| `/monitor/cache/list` | GET | `monitor:cacheList:list` | 缓存列表：分页查询缓存键值 |
| `/monitor/cache/clear` | DELETE | `monitor:cache:clear` | 清空缓存（`cacheName` 为空清空全部） |

- **服务监控采集**：`common/sysinfo`，**只用标准库**（Linux 读 `/proc/stat`、`/proc/meminfo`、`/proc/loadavg`、`/proc/mounts` + `syscall.Statfs`），
  **禁止引入 `gopsutil`**；平台相关代码用构建标签拆分（`sysinfo_linux.go` / `sysinfo_other.go`），字符串解析逻辑放平台无关文件以便单测。
  响应字段与前端监控页面约定一致（`cpuNum`/`memTotal`/`goVersion`/`sysFiles` 等），内存/磁盘单位 MB、使用率 %。
- **缓存监控**：基于 `common/cache`（进程内内存缓存，无 Redis）。新增业务缓存后调用 `cache.Register("名称", 实例)` 即会出现在监控与列表中；
  缓存列表只展示未过期条目，缓存值超过 200 字符截断。
- **新增监控类接口**：控制器放 `app/monitor/controller/`，服务放 `app/monitor/service/`，路由注册到 `app/monitor/controller/init.go` 的 `/monitor` 分组，
  并同步补充权限别名（若路径无法推导出权限标识，见 `app/system/middleware/auth.go` 的 `pathPermissionAlias`）。
  注意：种子菜单的按钮权限命名（`xxx:remove`/`xxx:edit`/`monitor:job:changeStatus` 等），
  开启 `AUTH_PERMISSION_ENABLED` 前需在 `pathPermissionAlias` 补齐这些映射，否则非超管角色会被拒绝。

### 1.13 模块新增与拆分

- 新增业务模块（如代码生成 `app/gen`）时，**新建 `app/<模块>` 独立目录**，不要塞进 `app/system`；
- 模块内固定结构：`domain/`（+`init.go` 的 `Models()`）、`service/`、`controller/`（+`init.go` 的 `InitRouter`）、`initialize.go`、`test/http/`；
- 在 `bootstrap/bootstrap.go` 中追加两行：`database.AutoMigrateAll(..., <模块>domain.Models())` 与 `<模块>.Initialize(r)`。

## 二、开发工具：just（开发 / 测试 / 打包 / 发布）

**统一使用 `just`（命令运行器，项目根目录 `justfile`）管理开发、测试、打包、发布。**

### 2.1 常用命令

| 命令 | 说明 |
| --- | --- |
| `just` / `just --list` | 查看全部可用命令 |
| `just init` | 初始化：检查项目依赖（有则绿勾 ✔，缺失自动安装 swag/just 等）+ `go mod tidy` |
| `just env dev` / `just env pro` | 环境切换：将 `.env.dev` / `.env.pro` 复制为 `.env` |
| `just encrypt '<明文>'` | 加密配置敏感值（AES-256-GCM），输出 `ENC(...)` 密文 |
| `just encrypt-env '<明文>'` | 加密并输出可粘贴到 `.env` 的配置片段（开关 / 密钥 / 密文） |
| `just decrypt 'ENC(...)'` | 解密配置敏感值（排查用） |
| `just dev` | 开发：启动项目（`go run main.go`，默认监听 :8080） |
| `just test` | 测试：`go test ./...` |
| `just vet` | 检查：`go vet ./...` |
| `just smoke [URL]` | 冒烟：对已启动实例跑读接口 + 全模块 CRUD 回归（`scripts/smoke.sh`，默认 `http://127.0.0.1:8080`） |
| `just gen-check [URL] [MYSQL_CMD]` | 代码生成深度校验：建临时表 → 导入 → 校验列配置推导 → 同步数据库 → 清理（`scripts/gen-check.sh`） |
| `just build` | 打包：编译供镜像使用的 **linux/amd64** 静态二进制 `admintpl-server` |
| `just release` | 发布：构建 Docker 镜像并推送远程仓库 |
| `just docker-run` | 容器运行：本地以容器方式启动（`--env-file .env` 注入配置） |
| `just docs` | 生成 swagger 接口文档 |

### 2.2 配置与环境切换

- **配置与代码分离**：`config/config.yaml` 只保留配置**结构**，具体值全部写在根目录 `.env` 中，通过 `${KEY}` / `${KEY:-默认值}` 占位符引用。
  - 优先级：**系统环境变量 > `.env` 文件 > `config.yaml` 中的默认值**。
  - `.env` 不入库（`.gitignore` 已忽略），环境模板 `.env.dev`、`.env.pro` 入库。
  - 可通过 `ENV_FILE` 指定其它 env 文件，通过 `CONFIG_NAME` 指定其它配置文件。
- **环境切换**：`just env dev` / `just env pro`（本质是把 `.env.dev` / `.env.pro` 复制为 `.env`）。
- `just dev` 在 `.env` 缺失时会自动按 `dev` 初始化。
- **配置加密（可选）**：敏感值（数据库密码、令牌密钥等）可用 AES-256-GCM 密文书写，实现在 `common/secret`
  （加解密复用 `github.com/freewu/crypto-go` 的 AES 封装 `aes.GetInstance("GCM")`），
  解密在配置加载阶段由 `common/config` 统一完成（`DecryptAll`），**业务与中间件代码不写解密逻辑**。
  - 开关 `CONFIG_ENCRYPT_ENABLED`：`false`（默认）全部明文；`true` 时解密所有含 `ENC(...)` 片段的值。
  - 密钥 `CONFIG_SECRET_KEY`：任意字符串，内部 SHA-256 派生 32 字节密钥（crypto-go 要求 16/24/32 字节）；更换密钥需重新加密。
  - 密文格式 `ENC(base64url(nonce||ciphertext||tag))`，支持整体加密（`DB_DSN=ENC(...)`）与
    局部加密（`DB_DSN=root:ENC(...)@tcp(127.0.0.1:3306)/admintpl?...`），明文密文可混用。
  - 失败策略：开关关闭却出现密文、密钥缺失、密钥不匹配或密文被篡改都会**启动失败**并给出明确提示。
  - 生成密文：`just encrypt '<明文>'`；输出 `.env` 片段：`just encrypt-env '<明文>'`；回读校验：`just decrypt 'ENC(...)'`。

### 2.3 流程约定

- 开发前：`just vet` + `just test` 确认无错误。
- 开发中：`just env dev` 切开发环境 → `just dev` 启动调试。
- 接口/数据库字段变更后：`just smoke` 对运行中的实例做回归（能直接发现列名与表结构不匹配类问题）。
- 开发完成：`just build` 打包 → `just env pro` 切生产配置 → `just release` 发布。
- 打包产物 `admintpl-server` 已加入 `.gitignore`，不入库。
- **容器运行**：镜像只含二进制与 `config/` 结构，不含 `.env`；配置通过环境变量注入：
  - 本地：`just docker-run`（等价于 `docker run --rm -it -p 8080:8080 --env-file .env admintpl-server:latest`）
  - 生产：`docker run -d -p 8080:8080 -e DB_DSN='...' -e SERVICE_DEBUG=false admintpl-server:latest`
  - 构建上下文已用 `.dockerignore` 裁剪（排除 `.git`、`docs`、`.env*` 等）。

## 三、开发完成总结（git message 规范）

**每次开发完成后，必须总结本次开发内容，用于 git commit message。**

### 3.0 提交流程（必须执行）

**每次开发完成后，必须 `git commit` 并 `git push` 到远程仓库。**

```bash
# 1. 查看变更
 git status
# 2. 暂存（按模块添加，避免误提交无关文件）
 git add app/system/controller/dict-type.go app/system/service/dict-type.go ...
# 3. 提交（自动载入 .gitmessage 模板）
 git commit
# 4. 推送远程
 git push
```

- 提交前先执行 `just vet` 与 `just test`，确认无错误。
- commit message 必须按下方 3.1 格式书写。
- 提交并推送成功后才算本次开发完成。

### 3.1 Commit Message 格式

```
<type>(<scope>): <中文描述>

- 新增/修改文件清单（路径）
- 功能点说明
- 修复的问题（如有）
- 验证结果（just vet / just test 通过）
```

### 3.2 type 类型

| type | 含义 |
| --- | --- |
| `feat` | 新增功能（新模块、新接口） |
| `fix` | 修复 bug |
| `refactor` | 重构（不改变功能） |
| `docs` | 文档变更 |
| `chore` | 构建/配置等杂项 |

### 3.3 示例

```
feat(system): 新增字典类型/字典数据模块

- app/system/controller/dict-type.go、dict-data.go
- app/system/service/dict-type.go、dict-data.go
- app/system/domain/dict-type.go、dict-data.go
- app/system/test/http/dict-type.http、dict-data.http
- 注册路由（controller/init.go）与 autoMigrate 模型（domain/init.go）
- 验证：just vet / just test / just build 通过
```

> 模板文件：`.gitmessage`（已通过 `git config commit.template` 配置，`git commit` 时自动载入）。

## 四、接口 swag 注解规范

**每个 HTTP 接口都必须使用 swag 注解**（项目使用 `github.com/swaggo/swag` 生成接口文档）。

### 4.1 必填注解

每个 handler 函数上方必须包含以下注解：

```
// List 获取xxx列表
// @Summary 获取xxx列表
// @Description xxx列表
// @Tags xxx管理
// @Param data query domain.XxxSearchRequest true "data"
// @Success 0 {object} response.Response{data=response.PageResult{list=[]domain.Xxx}} "{"code": 0, "msg": "success","data": { "list": [],"total": 0 } }"
// @Router /system/xxx/list [get]
// @Security
```

| 注解 | 说明 |
| --- | --- |
| `@Summary` | 接口摘要 |
| `@Description` | 接口详细描述 |
| `@Tags` | 接口分组（按模块） |
| `@Param` | 参数（query=GET 查询参数 / body=POST·PUT 请求体，类型用对应 Request 结构体） |
| `@Success` | 成功响应结构（返回体统一 `response.Response`，列表数据用 `response.PageResult{list=[]domain.Xxx}`） |
| `@Router` | 路由路径 + HTTP 方法，如 `/system/xxx/list [get]` |
| `@Security` | 安全标记（统一保留） |

### 4.2 规范要求

- **每个 handler 都必须写全注解**，与模板（`app/system/controller/department.go`）保持一致。
- 删除接口参数统一为 `request.IdsRequest`（业务表）或 `XxxDeleteRequest`（关系表）。
- 详情接口参数统一为 `request.GetById`。
- 修改接口 body 用 `XxxUpdateRequest`，新增接口 body 用 `XxxCreateRequest`。
- 参考文件：`app/system/controller/department.go`、`app/system/controller/dict-type.go`。

### 4.3 文档生成

```bash
# 生成文档（推荐）
just docs
# 等价于：
swag init -o ./app/swagger

# 访问
http://127.0.0.1:8080/swagger.json
```
